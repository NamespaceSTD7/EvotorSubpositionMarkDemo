# ДЕМО: марка в подпозициях набора — ошибка Evotor POS

Минимальная интеграция на `integration-library v0.6.32`, показывающая, что при возврате
через `PositionEdit` набора, в подпозицию которого установлена марка (код маркировки),
Evotor POS падает с диалогом «В приложении Evotor POS произошла ошибка».

## Установка
Установить APK (`app/build/outputs/apk/debug/app-debug.apk`) на Смарт-терминал.

## Воспроизведение
Завести в каталоге три товара:

| Наименование товара          | Тип товара   | Роль                                        |
|------------------------------|--------------|---------------------------------------------|
| `ДЕМО-НАБОР`                 | Обычный      | «набор», в подпозицию ставится марка        |
| `ДЕМО-НАБОР-БЕЗМАРКИ`        | Обычный      | «набор»-контроль, подпозиция без марки      |
| `ДЕМО-ВОДА`                  | WATER_MARKED | маркируемый товар, подпозиция набора        |

Продажа → добавить в чек только `ДЕМО-НАБОР` (воду добавлять **не нужно**):
1. Интеграция находит `ДЕМО-ВОДА` в каталоге **программно** (`ProductQuery` по имени),
   из-за чего при добавлении в чек маркируемого товара терминал саму марку НЕ запрашивает.
2. `ДЕМО-НАБОР` превращается в набор: подпозиция = позиция из карточки `ДЕМО-ВОДА`
   (тип `WATER_MARKED` приходит от карточки) + `setMark(код маркировки)`.
3. Сразу после применения результата появляется **«В приложении Evotor POS произошла ошибка»**.

Контроль: `ДЕМО-НАБОР-БЕЗМАРКИ` — тот же набор, но подпозиция БЕЗ марки →
ошибки нет.

Вывод: POS не поддерживает установку маркировки в подпозиции набора.

## Логи
Интеграция пишет в logcat с тегом `SubposMarkDemo` (тип подпозиции и значение марки).

## Сборка
```
gradlew assembleDebug
```
Gradle 7.5, AGP 7.4.1, Kotlin 1.7.20, compileSdk 31, JDK 17.
