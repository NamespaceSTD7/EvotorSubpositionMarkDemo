# ДЕМО: марка в подпозициях набора — ошибка Evotor POS

Минимальная интеграция на `integration-library v0.6.32`, показывающая, что при возврате
через `PositionEdit` набора, в подпозицию которого установлена марка (код маркировки),
Evotor POS падает с диалогом «В приложении Evotor POS произошла ошибка».

## Установка
Установить APK (`app/build/outputs/apk/debug/app-debug.apk`) на Смарт-терминал.

## Воспроизведение
Завести в каталоге два обычных товара (тип «Обычный товар», ничего больше не требуется):

| Наименование товара     | Поведение                        |
|-------------------------|----------------------------------|
| `ДЕМО-МАРКА`            | подпозиция `BEER_MARKED` **с** маркой → **ошибка POS** |
| `ДЕМО-БЕЗМАРКИ`         | подпозиция **без** марки → работает                    |

1. Продажа → добавить `ДЕМО-МАРКА` в чек.
2. Интеграция превращает позицию в «набор»:
   - подпозиция 1 — обычный товар;
   - подпозиция 2 — принудительно `BEER_MARKED`, марка = `Mark.RawMark(...)`.
3. Сразу после применения результата появляется **«В приложении Evotor POS произошла ошибка»**.

Тот же товар `ДЕМО-БЕЗМАРКИ` выдаёт ровно тот же набор, но подпозиция без марки —
ошибки нет.

Вывод: POS не поддерживает установку маркировки в подпозиции набора.

## Логи
Интеграция пишет в logcat с тегом `SubposMarkDemo` (тип подпозиции и значение марки).

## Сборка
```
gradlew assembleDebug
```
Gradle 7.5, AGP 7.4.1, Kotlin 1.7.20, compileSdk 31, JDK 17.
